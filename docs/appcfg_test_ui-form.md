## appcfg test ui-form

Test an individual or all UI form configurations

### Synopsis

Tests one or all UI form configurations by validating template output against
expected output files.

A UI form has three templates that can be tested:

form.gtpl
---------
Renders the form definition that is displayed to end-users. The template has
access to three data attributes: `data`, `actions`, and `customer`. Test data
for each attribute is configured in JSON files named after the attribute (e.g.
`data.json`, `actions.json`, `customer.json`) in the `_test_` folder or a dataset
subfolder.

Validation is run against the expected output file before comparing it to the
template output to ensure it conforms to the [form configuration format](https://help.gladly.com/developer-tutorials/docs/app-actions-setup#action-fields). The expected output file is named `expected_form.json` and
lives in the dataset folder under `_test_`.

action_result.gtpl
------------------
Creates the result displayed to the end-user after form submission. The template
has access to the `action` attribute which contains a field for the `inputs` that
were provided to execute the action and the `result` of the action. The template
also has access to the form attr values via a `formAttrs` attribute. Test
data is configured in an `action.json` and a `formAttrs.json` file respectively
and either located in the `_test_` folder or a dataset subfolder.

The rendered output must be valid JSON conforming to the [action response format](https://help.gladly.com/developer-tutorials/docs/app-actions-setup#form-errors).
Validation is run against the expected output file before comparing it to the
template output. The expected output file is named `expected_action_result.json`
and lives in the dataset folder under `_test_`.

action_inputs.gtpl
------------------
Optionally transforms the input values submitted via the form into the format
expected by the action. This template is only needed when a one-to-one mapping
between form field "attr" values and action inputs is not possible.

The template has access to an object where each field corresponds to an `attr`
value from the `form.gtpl` inputs. Test data is configured in a `formAttrs.json`
file either in the `_test_` folder or a dataset subfolder.

The rendered output must be valid JSON where each top-level field corresponds to
an input of the action defined in the action GraphQL schema. Validation is run
against the expected output file before comparing it to the template output. The
expected output file is named "expected_action_inputs.json" and lives in the
dataset folder under `_test_`.

Test datasets
-------------
Tests are organized into datasets. Each dataset is a sub folder under the `_test_`
folder. The folder name describes the scenario being tested (e.g. "success",
"no-customer"). Each dataset folder contains the expected output files for that
scenario, and optionally attribute JSON files that override the defaults in `_test_`.

When no `--data-set` flag is specified, all datasets are tested. Use `--data-set` to
target a single dataset.

The `add ui-form` command creates a default `success` dataset with stub test files.

Targets
-------
Use the `--target` flag to limit which templates are tested:

- `all` (default): tests `form.gtpl`, `action_inputs.gtpl` (if present), and `action_result.gtpl`
- `form`: tests only `form.gtpl`
- `inputs`: tests only `action_inputs.gtpl`
- `result`: tests only `action_result.gtpl`

Output
------
By default, test results are written to the console. Use `--output` file to write
results to `_test_/_output_/{timestamp}/{dataset}` instead.


```
appcfg test ui-form [ form name ] [flags]
```
